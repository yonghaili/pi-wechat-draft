# pi-wechat-draft

**把草稿填进微信输入框，但不替你按发送。** Windows + 微信 4.x 的桌面自动化，带常驻后台服务、逐字回读校验和一套"不打扰使用者"的执行纪律。

> English: see [README.en.md](README.en.md) for the full English documentation.

---

## 它和"又一个 wxauto 脚本"的区别

微信桌面自动化本身不难写，难的是**在别人的机器上、在别人正在用电脑的时候不出事**。这个仓库的价值主要是踩过的坑：

- **填入方式用 UIA `ValuePattern` 直写**，不用「点击输入框 + 剪贴板 Ctrl+V」。后者依赖坐标点击，实测在同一台机器上会出现"库报填写成功、输入框其实是空的"——因为它的坐标空间和真实屏幕位置对不上，而它自己的"有字没字"检查又会被上方聊天内容误判。
- **写入后逐字回读**：`SetValue` 之后再读一遍控件值，和要写的字逐字比对；还能读到控件自带的会话名（`chat_input_field` 的 Name 就是当前聊天对象），**先确认对象再写**。
- **不最小化任何窗口**：上游库自带的 `ensure_visible()` 会把与微信重叠的窗口全部最小化掉，等于把使用者的工作窗口收走。这里只用 `ShowWindow` 恢复微信自己。
- **抢前台用 Alt 键解锁法**：同一台机器四种方法连测，只有「合成一个 Alt 键事件 + `SetForegroundWindow`」能稳定抢到（10/10）；上游库的置顶法、`SwitchToThisWindow` 都失败。
- **常驻服务 + 文件队列**：微信 UI 操作永远只有一个执行者，不会两个请求同时抢微信；UI Automation 引擎常驻复用（就绪 0.8s，而不是每次冷启 3.8s）。
- **默认只填不发**：`send` 需要显式 `--confirm`，否则以退出码 9 拒发。

完整清单（含每条坑的现象、根因、验证方式）在 [SKILL.md](SKILL.md)。

## 安全模型

| 动作 | 默认行为 |
|---|---|
| `wx draft` | 把草稿填进输入框，**不发送**，回一张待确认卡片 |
| `wx send ... --confirm` | 真的发出（缺 `--confirm` 直接拒发） |
| `wx clear` | 清空输入框（撤掉草稿） |
| 其它 | 不转发、不加好友、不改微信设置/标签 |

设计前提：**发消息这件事，最后一按应该由人来做**。所以 agent 只填，你看一眼自己按回车；确实要代发时，用 `send --confirm` 并且以另一条链路回读确认。

## 环境要求

- Windows 10 / 11

- Python 3.10+
- Git Bash（命令行入口 `wx` 用它跑 shell 脚本；也可直接用 `scripts\wx.cmd`）

## 安装

```powershell
git clone https://github.com/yonghaili/pi-wechat-draft.git
cd pi-wechat-draft
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

`install.ps1` 会在仓库目录里建一个独立 venv 并装好依赖（不动全局 Python），最后打印自检结果。

可选：如果你想让它用**另一条独立链路**回读聊天记录做交叉验证（而不只依赖 UIA 回读），把一个只读微信读取器指给它：

```powershell
setx WX_READER "C:\tools\reader\rion_wechat_reader.py"
```

不配置也完全能用——只是少一层证据，`wx resolve`（口语名字解析）和原文回读会被跳过。

把客户端放进 PATH（Git Bash）：

```bash
echo 'export PATH="'"$PWD"'/scripts:$PATH"' >> ~/.bashrc
```

## 用法

```
wx draft  "<会话名>" "<文字>" [--now]           # 默认：只填不发；--now = 不等空闲，立即执行
wx send   "<会话名>" "<文字>" --confirm [--now] [--allow-high-risk]  # 真发（需你明确确认过）
wx check  "<会话名>"                    # 开会话 + 读屏 + 原文核对
wx clear  "<会话名>"                    # 清空输入框（撤稿）
wx context "<会话名>" [N]               # 只看最近 N 条原文（不碰界面）
wx resolve "<关键词>"                   # 口语叫法 → 候选会话名（需 WX_READER）
wx result <任务号>                      # 回查排队中的任务
wx svc start|stop|status|log            # 后台服务
```

```bash

写入方式：value_pattern
```

## 它是怎么工作的

```
你的命令 / agent
      │  写 job 文件
      ▼
<repo>/queue/<seq>.<id>.job
      │  串行领取（改名 .working，保证同一时刻只有一个执行者）
      ▼
wx_service.py（隐藏的常驻进程）
      │  ① 等一次真正的空闲（可配，见下）
      │  ② 恢复微信窗口（只碰微信自己，不最小化别人的窗口）
      │  ③ Alt 键解锁 → 切前台（UIA 树只有在前台才会物化）
      │  ④ 打开会话 → UIA ValuePattern 写入 → 逐字回读
      │  ⑤ 取消置顶 / 还原前台窗口与光标
      ▼
<repo>/queue/<id>.result  ← 客户端读取并打印证据
```

几个刻意的设计：

- **队列是文件**，不是 socket：可审计（`queue/*.result` 留着每次的证据）、可手工检查、服务挂了也不丢任务；服务启动时会把上次遗留的 `.working` 放回队列。
- **非阻塞客户端**：默认最多等 45s，超时就回「已排队，任务号 xxx」而不是失败——任务留在后台继续等一个合适的时机。
- **一个服务在进程列表里会显示成两个进程，这是正常的**：Windows 上 venv 的 `pythonw.exe` 是个「重定向器」，它会再起一个真正的解释器子进程，两者命令行完全相同（实测：父 6MB / 子 19MB 常驻）。PID 文件记的是真正在跑主循环的那个；`wx svc stop`（内部 `svc_sweep`）会把两者一起收掉。排查时别把它们当成“跑重复实例”。
- **空闲闸门可配**：`WX_IDLE_GATE`（写字的动作默认 2s）、`WX_IDLE_MAX_WAIT`（默认 300s，等不到就放回队列）。注意 `GetLastInputInfo` 在有 HID 噪声的机器上可能长期不空闲（本机实测 12 秒采样最长只有 0.3s），所以闸门**绝不允许无限等**。
- **前台闸门**：每次注入输入前检查 `GetForegroundWindow()` 是不是微信主窗，不是就放弃本次输入——防止字被打进别的窗口。

## 实测数据（微信 4.1.13.65 / Windows 11）

| 动作 | 总耗时 | 占用前台 |
|---|---|---|
| `check` | 3.2s | 1.9–2.8s |
| `send --confirm` | 4.9s | 4.5s |
| `draft`（冷启后首单会更慢） | 8.6s | 8.2s |

「占用前台」是微信停留在最前面的时长（操作完成后会把焦点还给你原来的窗口）。所有结果里都会打印这个数字。

## 静默与不打扰

「后台跑」和「别打扰我」是两件事。本工具的做法是**挑时机**，不是偷偷摸摸：微信 4.x 的文字输入必须走前台窗口（不在前台时它的无障碍树是空壳），所以「完全不碰屏幕」在这个技术栈上不存在。能做的是让你感觉不到它动过手。

**空闲闸门**：写字的动作（`draft`/`send`）只在鼠标键盘停止操作 ≥ `WX_IDLE_GATE` 秒后才执行。你一直在用电脑，任务就老实排在队列里，客户端回「已排队」而不是硬抢焦点。确需立刻执行加 `--now`（会被插到队首）。

**配置放运行期文件，不用改代码**：`<WX_DIR>/wx-service.env`（每行 `KEY=VALUE`，改完 `wx svc stop && wx svc start`）：

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `WX_IDLE_GATE` | `2` | 写字动作要求的空闲秒数。**建议调到 20**——默认 2 秒太激进，手停两秒就被抢焦点 |
| `WX_IDLE_GATE_RO` | `0.5` | 只读动作（`check`/`clear`）要求的空闲秒数 |
| `WX_IDLE_FALLBACK` / `WX_IDLE_FALLBACK_MIN` | `600` / `5` | 等满 10 分钟仍无长空闲（一直在用电脑）时，降级为「只要有 5 秒安静就执行」，避免任务被永久饿死在队列里。设 0 = 禁用降级 |
| `WX_IDLE_MAX_WAIT` | `300` | 单个任务最多盯多久空闲就放回队列（配合 `--now` 建议设 60） |
| `WX_RESTORE_BLOCKERS` | `1` | 还原上游库为让路而最小化的遮挡窗口 |
| `WX_OFFSCREEN` | `0` | `1` = 任务执行期间把微信窗口**挪到屏幕外**（屏幕上没有它）。前提是打开会话走无点击的 UIA 路径，离屏时会强制不回退到库的点击级联。首尾各有约 0.1–0.25s 露面，绕不过去（原因见下） |

**收尾还原**：任务结束会把焦点还给你原来的窗口；上游库为让开点击路径而最小化的遮挡窗口也会被还原（保留其最大化状态）。

**单个任务不会带走服务**：任务异常会被捕获、写进结果文件并回报，常驻服务继续运行。（曾经不是——一个任务抛异常会让服务进程静默退出，而客户端只看到「已排队」，表象就是「没反应」。）

**`--now` 不是免费的**：你正操作电脑时它更容易失败——实测活跃操作期间出现过 UIA 的 `COMError` 与 `int(None)`。空闲闸门不只是礼貌，也提高成功率。

**实测**（2026-09-21）：一直在用电脑时 `wx draft` 返回「已排队」而不抢焦点；停手 **30.7 秒**后同一个任务自动跑完，`ok=True`、占用前台 11.1s、焦点已归还。

**「把微信搬到屏幕外」现在成立了（2026-09-22 实测翻案）**：上面那段曾是 2026-09-21 的否定结论，理由只有一条——打开会话靠物理点击（`SetCursorPos` + `mouse_event`），窗口不在屏幕上就点不到。现在打开会话与写入都走**零点击**的 UIA 路径，只剩「输入要有前台」这一条约束，而窗口即使不在屏幕上也能是前台。开 `WX_OFFSCREEN=1` 后，用 0.08s 间隔的独立采样验证：**任务期间只观测到窗口在屏幕外**（前台窗口是它，矩形停在 `-25600`），写入正常落在输入框。

三条实测教训（别重复踩）：

1. **不能用 `SetWindowPlacement` 改 `rcNormalPosition` 来搬**。窗口处于最小化时，随后的 `SW_RESTORE` 不走那个位置——实测任务期间窗口出现在屏幕正中，任务照样“成功”，看起来像没生效。必须 `SetWindowPos` 直接搬，并且用 `GetWindowRect` 现场校验。
2. **不能在搬完之后再调库的 `ensure_visible`/`SW_RESTORE`**（我们的 `ensure_window_usable` 同理）：它会把窗口拉回屏幕。离屏成功后这一步必须跳过。
3. **首尾各有约 0.1–0.25s 的露面**：窗口最小化时它的 UIA 树是空壳，必须先恢复成可见才能操作，而一恢复就出现在屏幕上（微信自己也会用缓存的几何把窗口摆回 `(1297,243)`）。这是物理约束，不是实现问题；能保证的是**真正干活的那段时间窗口在屏幕外**。

## 发送前的敏感内容闸门

**第一层·离线敏感内容闸门（确定性，不联网）**：`send` 在碰鼠标键盘之前先扫文本，命中下列五类直接拒发（`method: blocked_high_risk`，实测 0.8s 完成、**占用前台 0.0s**）：

| 类别 | 例子 |
| --- | --- |
| 16-19 位长数字 | 银行卡/账号 |
| 验证码 | “验证码是 8848” |
| 密码/密钥 | “密码发我一下”、api key |
| 证件/账号信息 | “卡号：6222…” |
| 转账/付款金额 | “转账 5000 给你” |

只拦「客观不可逆」的两类（金额与凭证）——**不拦普通金额和时间的表述**（“明天上午9点见”“请你吃饭”照发），因为那是日常沟通的常态。确实要照发加 `--allow-high-risk`，会在日志里留一行“高风险内容经 --allow-high-risk 放行”。

## 打开会话：无点击路径（2026-09-21 实测）

上游库打开会话用的是「点击搜索框 + 剪贴板 Ctrl+V + SendKeys + 物理点击结果项」——三个易碎环节，而且它为此必须先把你挡着微信的窗口**最小化**；失败时还会进入无外部超时的级联（实测同一会话一次 **63.5s** 失败、历史最坏占用前台 **75s**）。

现在默认改走自己的路径（`WX_OPEN_MODE=auto`）：

1. 先读当前输入框控件的会话名（`current_chat_raw`，便宜版现场读），已是目标就直接用；
2. 否则 UIA `ValuePattern` **直写搜索框** → 纯 UIA 读结果列表、确认**第一条结果就是目标**（不确认绝不敢回车——开错会话比打不开更糟）→ `SetFocus` + 回车 → 现场校验会话名。

效果（本机实测，含之前 63.5s 失败的那个会话）：**打开 2.4-2.6s、全部成功**，占用前台从 8-13s 降到 5.3-6.0s；不点鼠标、不用剪贴板、不跑 OCR，**也不再把你的窗口最小化**。`WX_OPEN_MODE=library` 退回旧行为，`=uia` 则失败即快速失败、绝不进库的级联。

**试过并否定的两条**（别重复走）：① 搜索结果项用 `Invoke`/`SelectionItem` 打开 —— 搜索能被 UIA 写进去，但 Invoke 打开的是**独立聊天窗口**（主窗输入框不变、校验必然失败）；② 侧栏列表项虽然能用 UIA 枚举（`AutomationId = session_item_<会话名>`），但 `Select()`/`Invoke()` **不能真正切换会话**（白等 2.4s），而且它是虚拟列表、看不到非置顶会话、也没有 UIA 滚动。

## 局限（先说清楚）

- **做不到完全无感，但能做到“干活的时侯不在屏幕上”。** 微信 4.x 的输入框只有在窗口是前台时才出现在无障碍树里；窗口不在前台（或最小化）时 UIA 树是空壳（`chat_input` / `search_box` 全是 `None`），所以“不切前台静默写入”这条路不存在。能做的两件事：① 把占用时间压短（打开会话 63.5s → 2.4s）；② 开 `WX_OFFSCREEN=1` 把窗口挪到屏幕外，干活那段时间屏幕上没有它（首尾各有约 0.1–0.25s 露面）。
- **只读永远不要前台。** 只是想知道“最近说了什么、要不要回”，用 `wx peek "<会话名>"`（解密本地库，实测采样期间微信窗口 0 次露面）或 `wx context`；`wx check` 只在需要看**输入框里现在有什么**时才用（它要开窗口）。`wx doctor` 会把当前模式、现场窗口状态与占用基线一次列出来。
- **必须要微信窗口可见**（最小化/托盘状态会被先恢复；托盘时 `Get-Process` 的 `MainWindowHandle` 是 0，脚本用 `EnumWindows` + `ShowWindow` 恢复，不会多开实例）。
- **只测过微信 4.x**（本机 4.1.13.65）。微信大版本升级后 UIA 类名/自动化 ID 可能变，`wx svc log` 会给出症状。
- **不做群发、不做定时任务、不碰 hook/协议层。**
- 依赖的上游库 `wechatauto-replica` 是第三方项目；本仓库对它的**返回值一律不采信**，所有判定都走自己的回读/像素检测。

```bash
git clone https://github.com/yonghaili/pi-wechat-draft.git ~/.pi/agent/skills/wechat-draft
```

## 自检与贡献

```bash
python scripts/selfcheck.py                                    # 语法 / 换行 / ASCII / 隐私与凭据扫描
EXTRA_DENY='你的名字|某个联系人' python scripts/selfcheck.py      # 本地追加私有词，不必提交
```

自检脚本本身不含任何个人姓名（否则它自己就成了泄漏源），只在扫描时跳过自己。CI 在 `.github/workflows/selfcheck.yml`，任务只有一步：`python scripts/selfcheck.py`——和你在本地跑的是同一份检查。（提示：推送 workflow 文件要求 token 带 `workflow` scope，否则 GitHub 会直接拒收；补授权用 `gh auth refresh -s workflow`。）
